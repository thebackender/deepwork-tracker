# deepwork-tracker

Track deep work sessions on the way to 10,000 hours. Python (standard library only), Markdown logs, git, and an animated statistics page in the browser.

## Usage

```
dw add 90 thesis "Wrote chapter 2 intro"   # add a record in one line
dw add                                     # or answer prompts for each field
dw stats                                   # open the statistics page
dw sync                                    # update the public file from your private log
dw backup                                  # back up all records now (.md + .xlsx)
```

The time is the session's **start** time: `dw add 90 …` at 11:00 records `09:30`.

## Two log files

| File | Contains | Git |
|---|---|---|
| `deepwork_logs.md` | Full records: date, time, minutes, project, description | **Ignored.** Stays on your computer, backed up automatically (see below). |
| `deepwork_logs.public.md` | Date and minutes only | Generated by `dw`. You commit and push it to GitHub. |

- Only write to `deepwork_logs.md`, either through `dw add` or by editing it by hand.
- `dw add`, `dw stats` and `dw sync` regenerate the public file, including your manual edits. `dw` never commits: commit `deepwork_logs.public.md` yourself (VS Code's Source Control panel or `git commit`), then push.
- Commit times are visible on GitHub. To hide when you work, commit at a different time than your sessions, e.g. once a day or once a week.
- `deepwork_logs.public.md` is **read-only**, so it can't be edited by hand. `dw` unlocks it only while regenerating it. Git can still commit, discard or check it out, and the next `dw` run locks it again. In VS Code, `.vscode/settings.json` also opens it in a read-only editor, so VS Code's "Overwrite" save option can't bypass the lock.

## Safety check

Before doing anything, `dw add`, `dw stats` and `dw sync` compare the **date and minutes of past records** in `deepwork_logs.md` with `deepwork_logs.public.md`. If something was changed, deleted or added in the past, you see the differences:

```
WARNING: past records in deepwork_logs.md don't match deepwork_logs.public.md:
  - 2026-10-21 | 60 min   (in public log, not in your log)
  + 2026-10-21 | 75 min   (in your log, not in public log)
Did you change these on purpose? Update the public log [y/N]:
```

- **y:** you fixed something on purpose, so the public file is updated and the command continues.
- **N** (default): nothing is saved. `dw add` stops, and the public file and backups stay untouched. Restore `deepwork_logs.md` from a backup, or fix it, and try again.
- `dw stats` still opens the page on N, but doesn't update the public file.
- This also protects you if `deepwork_logs.md` gets lost or emptied: the public file and backups won't be overwritten with the damaged version.

## Backups

When you add the **first record of a new day**, `dw add` first copies `deepwork_logs.md` to your backup folder. At that moment the log holds every record from your first one up to the last day you logged, so a backup never contains a half-finished day.

```
~/deepwork-backup/
├── deepwork_logs-2026-10.md   everything up to the end of October (final)
└── deepwork_logs-2026-11.md   everything up to the last logged day in November (updated daily)
```

- **`dw backup`** backs up on demand: all records, including today's, into the same monthly `.md` and `.xlsx` files (named after the newest record's month). The next automatic backup replaces it with the up-to-yesterday version as usual.
- **One file per month**, named after the month of its newest record. The current month's file is replaced each new day. Once the next month starts, the previous file stays as it is for good.
- **Locked:** backup files are read-only and the backup folder is locked, so backups can't be edited, renamed or deleted, not even with `rm -rf`. Only `dw add` unlocks them for the moment it saves a backup. To delete backups on purpose, unlock the folder first: `chmod u+w <backup folder>`.
- **Restore:** copy a backup file back to `deepwork_logs.md` (the copy will be read-only too, so make it writable again, e.g. `chmod u+w deepwork_logs.md`).
- **Excel copy:** each backup is also saved as an Excel file with the same name, e.g. `deepwork_logs-2026-10.xlsx`, with one row per record (Date, Time, Duration, Project, Description). It opens in Excel, LibreOffice and Google Sheets, works with any language and is read-only and locked the same way.
- **Location:** set `DW_BACKUP_DIR` (and `DW_XLSX_BACKUP_DIR` for the Excel copies) in `.env` (copy `.env.example` to `.env`). Without them, both go to `~/deepwork-backup`. `.env` is ignored by git, so your path stays private.
- Backups stay on this computer. `deepwork_logs.public.md` on GitHub also holds every date and duration.

## Setup

Needs Python 3.8+ and git.

- **Linux / macOS:** add to `~/.bashrc` or `~/.zshrc`:
  `alias dw="python3 /path/to/deepwork-tracker/dw.py"`
- **Windows:** add the project folder to your `PATH`, and `dw.bat` will make `dw` work.

## Files

| File | What it is |
|---|---|
| `dw.py` | `add` and `stats` commands. Only `read_records()`, `write_record()` and `write_public()` know the file format. |
| `xlsx_backup.py` | Makes the Excel copies of backups (standard library only) |
| `web/` | Statistics page: `index.html`, `style.css`, `app.js` (no libraries). Uses the full private log. |
| `web/data.js` | Generated by `dw stats` from the private log, not committed |
| `docs/DEEPWORK_RULES.md` | What counts as deep work |
